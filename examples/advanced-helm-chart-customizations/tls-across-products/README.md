# TLS Across Products

Every JFrog Helm chart uses the same two-layer TLS model — JFrog Access acts as an internal Certificate Authority signing node-to-node traffic, while Nginx (or a product's own router) terminates external/inter-product TLS — but the exact key path differs by chart, and by whether the chart is deployed standalone or as a `jfrog-platform` subchart. This topic shows the same model applied to each chart.

<details>
  <summary>Artifactory</summary>

`access.accessConfig.security.tls: true` turns on Access as the internal CA. `nginx.tlsSecretName` points the external HTTPS listener at a pre-existing Kubernetes TLS Secret — required on a fresh install once `nginx.https.enabled` (the default) is left `true`.

See [tls-artifactory-values.yaml](tls-artifactory-values.yaml).

```shell
kubectl create secret tls artifactory-tls --cert=tls.crt --key=tls.key
helm upgrade --install artifactory jfrog/artifactory -f tls-artifactory-values.yaml
```
</details>

<details>
  <summary>Artifactory HA</summary>

Same two keys, same shape as standalone Artifactory — `access.accessConfig.security.tls` and `nginx.tlsSecretName` are not renamed or renested for the HA chart. The only HA-specific detail: `nginx.generateSelfSignedCert` (dev/test fallback) internally generates its cert using the `artifactory-ha.fullname` template helper for the certificate's DNS names, not `artifactory.fullname` — this only matters if you're reading the chart's own templates, not something you set yourself.

See [tls-artifactory-ha-values.yaml](tls-artifactory-ha-values.yaml).

```shell
kubectl create secret tls nginx-tls-secret --cert=tls.crt --key=tls.key --namespace artifactory-ha
helm upgrade --install artifactory-ha jfrog/artifactory-ha --namespace artifactory-ha -f tls-artifactory-ha-values.yaml
```
</details>

<details>
  <summary>RabbitMQ (Xray)</summary>

Xray bundles RabbitMQ as a subchart. TLS is controlled by two mirrored blocks — `global.rabbitmq.auth.tls.*` (read by the Xray container to decide whether to connect over TLS) and `rabbitmq.auth.tls.*` (read by the RabbitMQ subchart itself to decide whether to terminate TLS) — both must be set to the same value. The auto-generate-vs-bring-your-own toggle is `autoGenerated` (camelCase); the lowercase `autogenerated` is not a real key and is silently ignored.

See [tls-rabbitmq-values.yaml](tls-rabbitmq-values.yaml).

```shell
helm dependency build stable/xray
helm upgrade --install xray jfrog/xray -f tls-rabbitmq-values.yaml
```
</details>

<details>
  <summary>JFrog Platform</summary>

The full multi-product picture: Access is the CA for Artifactory, and Xray's and Distribution's routers are switched to verify (rather than skip) Access's certificate. Every value keeps its standalone-chart path, just prefixed with the subchart name — see [platform-vs-standalone-nesting](../platform-vs-standalone-nesting).

See [tls-jfrog-platform-values.yaml](tls-jfrog-platform-values.yaml).

```shell
kubectl create secret tls nginx-tls-secret --cert=nginx.crt --key=nginx.key -n jfrog-platform
helm upgrade --install jfrog-platform --namespace jfrog-platform --create-namespace jfrog/jfrog-platform -f tls-jfrog-platform-values.yaml
```
</details>
