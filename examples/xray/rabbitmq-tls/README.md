# RabbitMQ TLS

This example enables TLS on the bundled RabbitMQ instance that a standalone Xray install uses for messaging. RabbitMQ is shared between the `global` block (read by Xray) and the `rabbitmq` subchart's own block (read by the RabbitMQ pod itself) — both must be kept in sync.

See the [values-rabbitmq-tls.yaml](values-rabbitmq-tls.yaml) for the configuration example.

## How it works

- `global.rabbitmq.auth.tls.*` and `rabbitmq.auth.tls.*` must be set to the same value — the `global` copy is what Xray uses to decide whether to connect over TLS, and the `rabbitmq` copy is what the RabbitMQ subchart uses to decide whether to terminate TLS at all.
- The auto-generate-vs-bring-your-own toggle is `autoGenerated` (camelCase). This is easy to get wrong — the lowercase form `autogenerated` is not a real key and is silently ignored by the chart, leaving TLS certs unconfigured.
- Leaving `autoGenerated: true` (the default when TLS is enabled) has RabbitMQ generate its own self-signed certificate. To bring your own certificate instead, set `autoGenerated: false` and provide `existingSecret` under `rabbitmq.auth.tls` (and mirror the reference under `global.rabbitmq.auth.tls.existingSecret`).
- `rabbitmq.auth.password` must differ from the chart's literal default (`"password"`) or the install is refused outright — this is unrelated to TLS itself.

## Deploy

Always apply a sizing file to provide the correct resources to the containers. Download a sizing configuration (for example, `xray-xsmall`):

```shell
curl -fsSL https://raw.githubusercontent.com/jfrog/charts/master/stable/xray/sizing/xray-xsmall.yaml \
  -o xray-xsmall.yaml
```

Install Xray with the following command:

```shell
helm dependency build stable/xray
helm upgrade --install xray jfrog/xray -f values-rabbitmq-tls.yaml -f xray-xsmall.yaml
```
